# АВИОР CRM

Внутренняя система сервиса АВИОР (Москва, Можайское шоссе 4к1). Постепенно
заменяет ЛайвСклад: учёт ремонтов, клиентов, склада, финансов, интеграция
с сайтом по статусу ремонта, SMS-уведомления.

> Полное и всегда актуальное состояние проекта (инфраструктура, миграции,
> секреты, бэклог) — в [`PROJECT_STATE.md`](./PROJECT_STATE.md). Этот файл
> нужно читать в начале каждой новой рабочей сессии по проекту.

## Инфраструктура АВИОР — все сайты на одном VPS

Этот репозиторий — только CRM. Она — один из четырёх сайтов на одном
сервере (Ubuntu 26.04, Nginx + PHP-FPM 8.5). Чтобы вести весь проект
целиком, а не кусками, вот карта всех четырёх:

| Домен | Что это | Репозиторий | Деплой на сервер |
|---|---|---|---|
| **cms.avior.moscow** | Эта CRM (заказы, клиенты, финансы) | `vahmedov-code/cms_avior` (этот) | `git pull` в `/var/www/cms` |
| **avior.moscow** | Основной публичный сайт сервиса | `vahmedov-code/Avior-site` (публичный) | `curl` файл-за-файлом из `raw.githubusercontent.com` в `/var/www/avior` — **не git-репозиторий на сервере** |
| **shop.avior.moscow** | Интернет-магазин комплектующих/б.у. устройств (Laravel) | отдельный (детали — уточнить в PROJECT_STATE.md, если есть) | своя схема деплоя, отдельная БД |
| **ux.avior.moscow** | Лендинг «AVIOR UX» — сайты для мастеров и малого бизнеса (портфолио услуг веб-разработки Вейса) | `vahmedov-code/avior-ux` (публичный) | React + TypeScript + Vite + Tailwind — **нужна сборка** (`npm run build`), не голые файлы как у avior.moscow; способ деплоя на сервер уточнить у Вейса |

**Важно:** у каждого сайта — свой репозиторий и свой способ деплоя, они
не связаны между собой на уровне кода. Общее у них — только физический
сервер и то, что все они упомянуты для координации (например, единый
скрипт бэкапа `ops/backup-avior.sh` в этом репозитории бэкапит все четыре
сразу — БД и файлы). Если правите `avior.moscow` — это отдельный
репозиторий, клонировать/пушить нужно его, а не этот. Токен доступа для
пуша — свой для каждого репозитория (fine-grained, привязан к конкретному
репо), не путать между собой.

Пробрасывать общие nginx-конфиги/SSL этих сайтов при работе над CRM —
**нельзя трогать**, они настроены отдельно и не входят в зону
ответственности этого репозитория.

## Что уже готово (эта CRM)

- Авторизация сотрудников (логин/пароль, сессии, пароли на bcrypt), роли
  `admin`/`manager`.
- Панель управления с сеткой модулей + счётчики заказов по статусу
  (Новые/В работе/Отложенные/Готовые/Выданные), кликабельные.
- **Клиенты** — база, поиск, история заказов, источник обращения (авито,
  яндекс, 2гис, google карты, сарафан, с улицы).
- **Заказы** — единый список с трёх точек входа (ремонт, сборка ПК, памятка
  по аккаунту), статусы (принят → диагностика → согласование → в ремонте →
  готов → выдан / отказ), лог смены статусов, комплектующие и услуги по
  заказу (с себестоимостью для расчёта прибыли), сортировка по клику на
  заголовок столбца, переключатель вида список/плитки на мобильном,
  визуальный пикер типа устройства с иконками, подсказки автозаполнения
  (модель/поломка — из истории + встроенный каталог популярных моделей),
  удаление заказа (только admin).
- **Сборка ПК** и **Памятка по аккаунту** (Apple ID/Google, пароли не
  хранятся в БД) — отдельные формы создания заказа.
- **Квитанция о приёмке** и **Акт выполненных работ** — печать, QR-код на
  публичный статус, отправка клиенту через WhatsApp/Telegram/Email.
- **Финансы** и **Аналитика** — выручка/себестоимость/расходы/прибыль по
  периодам, источники клиентов, частые типы устройств, прибыльность.
- **SMS** — три поддерживаемых провайдера (SMS.ru, SMSC.ru, Android-шлюз
  через собственный телефон), шаблоны с автоподстановкой суммы/ссылки на
  статус, настраивается в интерфейсе (Настройки), без правки файлов.
- **Настройки** (`settings.php`, только admin) — реквизиты компании,
  юридические/банковские реквизиты, SMS-провайдер, site_url — всё через
  форму, хранится в БД. Задел под white-label.
- **Сотрудники** (`employees.php`, только admin) — добавление/удаление,
  роли, сброс пароля.
- Публичный **API статуса ремонта** (`public/api/status.php`) — питает
  виджет статуса на `avior.moscow`.
- **AI-сводка** (`public/api/ai/summary.php`) — токен-защищённый read-only
  JSON для анализа ассистентом (заказы/финансы/клиенты за период).
- **API для мобильного приложения** (`public/api/mobile/*.php`) — токен-
  аутентификация, клиенты, заказы, смена статуса. Полная спецификация и
  готовый Kotlin/Retrofit-каркас — в [`docs/MOBILE_API.md`](./docs/MOBILE_API.md).
- **Автоматический бэкап** всей инфраструктуры (эта CRM + все сайты) —
  `ops/backup-avior.sh`, см. [`docs/BACKUP.md`](./docs/BACKUP.md).

## Стек

PHP 7.4+/8.x (без фреймворка, только PDO) + MySQL 5.7+/8.0. Никаких
build-шагов и composer-зависимостей — можно просто скопировать файлы на
хостинг и открыть в браузере.

## Структура проекта

```
cms-avior/
  config/
    config.example.php   ← скопировать в config.php и заполнить
  public/                ← корень сайта (document root указывает СЮДА)
    index.php            ← панель управления
    login.php / logout.php / setup.php
    clients.php / client_view.php
    repairs.php / repair_new.php / repair_view.php
    settings.php          ← настройки (только admin)
    employees.php         ← сотрудники (только admin)
    finance.php / analytics.php
    smeta-sborka-pk.html ← форма сметы на сборку ПК (легаси, вне общего списка заказов)
    api/status.php       ← публичный API статуса ремонта
    api/ai/summary.php   ← AI-сводка для анализа ассистентом
    api/mobile/          ← токен-API для Android-приложения
    assets/css/style.css
  src/                    ← общий PHP-код (не должен быть доступен напрямую из браузера)
  sql/schema.sql          ← схема базы данных
  sql/migrations/         ← точечные миграции для уже развёрнутой БД
  ops/backup-avior.sh     ← единый скрипт бэкапа всей инфраструктуры
  docs/                   ← вспомогательные материалы, инструкции, примеры
```

Подробная инструкция по установке на сервер — в [`docs/DEPLOY.md`](./docs/DEPLOY.md).

## Локальная разработка

Если понадобится проверить локально:

```bash
cd cms-avior
php -S localhost:8000 -t public
```

(нужен PHP 7.4+ и настроенная в `config/config.php` база MySQL,
доступная с этой машины).
